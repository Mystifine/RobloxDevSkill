# Passes and products on Roblox

Creating, updating and checking an experience's passes and developer products through Open Cloud, beside [monetization.md](monetization.md), which decides what they are, what they cost and their art. The key and its handling: [uploading.md](../safety/uploading.md).

- **Resolve an id the user calls a place id** before acting on it: `universes/v1/places/{id}/universe`, then `games/v1/games?universeIds={id}`, and report the game's name and owner. Universe ids now reach the size place ids once had: one such id returned no universe as a place and was another creator's script as an asset.
- **Reuse a developer product or pass before creating one** *(default)*, in place: `PATCH https://apis.roblox.com/developer-products/v2/universes/{id}/developer-products/{productId}` and `.../game-passes/v1/universes/{id}/game-passes/{passId}`, multipart with name, description and imageFile, return 204 and keep the ids. They need the project's key with `developer-product:write` and `game-pass:write` (below). Snapshot them first and diff the change against it (a dry run): a rename shows at once in any game still on that universe, so dashboard changes ship with the publish that grants them. Keep every product the game sells on sale *(default)*.
- **Create the rest with the key, as multipart:** `POST https://apis.roblox.com/game-passes/v1/universes/{universeId}/game-passes` and `POST https://apis.roblox.com/developer-products/v2/universes/{universeId}/developer-products`, each a multipart form with `name`, `description`, `price`, `isForSale` and `imageFile` (the product's art from the icon family: [monetization.md](monetization.md#products-and-prices)), and no pricing switch (below). One script created 71 in about a minute and wrote the new ids into the game's constants.
- **Studio MCP's `open_cloud_invoke` cannot write them:** it listed both write scopes but could not PATCH them, and in another project it read passes and products (`game-pass:read`, `developer-product:read`) while refusing `game-pass:write` and `developer-product:write` as "not granted", before and after a Studio restart; it also refused files outside the folders approved for uploads. Use the project's key; when it answers 401, check its variable name before calling it dead ([uploading.md](../safety/uploading.md)).
- **`storePageEnabled` is write-only through the API:** a multipart `PATCH` with no file set it (204), and the `GET` never reports it back, so a read cannot confirm it: keep what was sent in the run's log. A create that sends no `storePageEnabled` leaves the listing to Roblox, so follow a batch of creates with a `PATCH` of it per product (82 of 82 answered 204).
- **A batch logs every item and retries a 5xx once, alone:** 71 `PATCH` calls with a new `imageFile` returned 204 except one, 504 "upstream request timeout"; that item retried alone returned 204.
- **Managed Pricing is switched per item by `isManagedPricingEnabled`,** a multipart `PATCH` carrying that field alone; the older `isRegionalPricingEnabled` answered 204 and changed nothing (two passes and two products: their update times did not move). Until the owner accepts Managed Pricing for that experience on Creator Hub (the game, Monetization, Managed Pricing), the switch answers 400 `InvalidManagedPricing`, "Managed pricing must be accepted before it can be enabled". The acceptance belongs to one experience, not its group: a new universe under the same group refused the switch again. Items created through Open Cloud before the acceptance came up off, though Roblox's docs say new items enroll automatically. Once it was accepted, 82 switches were accepted, and the creator lists read back `isManagedPricingEnabled` true with `RegionalPricing` in `priceInformation.enabledFeatures` on the 74 meant to have it, and false on the 8 gift products. Which items get it: [monetization.md](monetization.md#products-and-prices).
- **Moving a game to a new universe:** passes and products belong to their universe, and the new one listed 0 of each (`GET .../creator`, 200), so recreate every one there (82 in about two minutes with the same key) and write the new ids into the game. Its DataStores and MessagingService start empty too. Assets owned by the same group carry over: images, sounds and animations needed nothing, since the group still owns the experience. Keep the creation receipts per universe, so an old universe's ids never stop an item being created in the new one; then accept Managed Pricing for the new experience and set it per item.
