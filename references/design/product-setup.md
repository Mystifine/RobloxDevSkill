# Passes and products on Roblox

Creating, updating and checking an experience's passes and developer products through Open Cloud, beside [monetization.md](monetization.md), which decides what they are, what they cost and their art. The key and its handling: [uploading.md](../safety/uploading.md).

- **Resolve an id the user calls a place id** before acting on it: `universes/v1/places/{id}/universe`, then `games/v1/games?universeIds={id}`, and report the game's name and owner. Universe ids now reach the size place ids once had: one such id returned no universe as a place and was another creator's script as an asset.
- **Reuse a developer product or pass before creating one** *(default)*, in place: `PATCH https://apis.roblox.com/developer-products/v2/universes/{id}/developer-products/{productId}` and `.../game-passes/v1/universes/{id}/game-passes/{passId}`, multipart with name, description and imageFile, return 204 and keep the ids. They need the project's key with `developer-product:write` and `game-pass:write` (below). Snapshot them first and diff the change against it (a dry run): a rename shows at once in any game still on that universe, so dashboard changes ship with the publish that grants them. Keep every product the game sells on sale *(default)*.
- **Create the rest with the key, as multipart:** `POST https://apis.roblox.com/game-passes/v1/universes/{universeId}/game-passes` and `POST https://apis.roblox.com/developer-products/v2/universes/{universeId}/developer-products`, each a multipart form with `name`, `description`, `price`, `isForSale`, `isRegionalPricingEnabled` and `imageFile` (the product's art from the icon family: [monetization.md](monetization.md#products-and-prices)). One script created 71 in about a minute and wrote the new ids into the game's constants.
- **Studio MCP's `open_cloud_invoke` cannot write them:** it listed both write scopes but could not PATCH them, and in another project it read passes and products (`game-pass:read`, `developer-product:read`) while refusing `game-pass:write` and `developer-product:write` as "not granted", before and after a Studio restart; it also refused files outside the folders approved for uploads. Use the project's key; when it answers 401, check its variable name before calling it dead ([uploading.md](../safety/uploading.md)).
- **`storePageEnabled` is write-only through the API:** a multipart `PATCH` with no file set it (204), and the `GET` never reports it back, so a read cannot confirm it: keep what was sent in the run's log.
- **A batch logs every item and retries a 5xx once, alone:** 71 `PATCH` calls with a new `imageFile` returned 204 except one, 504 "upstream request timeout"; that item retried alone returned 204.
