# Uploading (Open Cloud)

- **Gate every upload.** Moderation screens each new upload with its own rules whatever the experience's label, can misfire, and can strike the uploading account.
  - Reuse an existing asset when one does the job.
  - Screen the file at full size and at 128 px against [no-gore.md](no-gore.md), and [characters.md](characters.md) for character art; name it plainly. Look before the upload command runs, in an earlier step, a repaint or recolor included.
  - Upload one asset of a new kind first and wait: poll `GET https://apis.roblox.com/assets/v1/operations/{operationId}` until `done`, and go on only when `response.moderationResult.moderationState` is `Approved`.
  - Never upload to test moderation or resend a rejected file unchanged. For a rejection that looks wrong, pause the batch and appeal it.
- **Use the project's Open Cloud API key when one is available** (from its ignored `.env` or secret store), for every asset type and experience operation; without one, ask the user. Never search other projects or their `.env` files for one. A key the user gives you goes in one file in the session's scratch folder, reaches the upload only as `--env-file`, and is deleted when the uploads are done; then search the project to confirm it did not leak, and tell the user that a key pasted into a chat should be rotated. Never print the key or copy it into source, manifests, logs or Studio. The content rules (the audit in [assets.md](assets.md), [characters.md](characters.md), [no-gore.md](no-gore.md)) apply to every upload.
- **Upload with [scripts/upload_asset.py](../../scripts/upload_asset.py)** `FILE [FILE ...] --group ID` (or `--user ID`): it waits for moderation, exits 0 only when approved, and stops a batch at the first file that is not. With `--manifest assets.json` it keeps ids by file stem and reuses what is approved at the same hash, so a batch can be rerun after any change.
- **A Decal upload's id is not its image's id.** `upload_asset.py` uploads images as Decals and returns the Decal's id, which an ImageLabel rejects ("Asset type does not match requested type"). Read the image id from the Decal's `Texture` (`InsertService:LoadAsset(decalId)` in Studio) and store that.
- **The experience's owner must own what it loads.** Read it in Studio first (`game.CreatorType`, `game.CreatorId`) and set `creationContext.creator` to that group (`groupId`) or user. An animation plays only in experiences owned by its creator, so one owned by anyone else never loads; Studio publishing (`AssetService:CreateAssetAsync`) must target the same creator. Upload animations as a `.rbxm` saved from Studio; Roblox warns that files edited elsewhere may fail.
  - **Wrong owner, the signs:** a Model fails `InsertService:LoadAsset` in Studio ("User is not authorized to access Asset"), and a user's key cannot grant a group's experience use of it (`CannotManageSubject`).
  - **A group's experience with only a user's key: try in order**, before asking the user or making anything public:
    1. Upload to the group with that same key (`upload_asset.py FILE --group <CreatorId>`). It works when the key's user may manage the group's assets (approved and loading in the group's place, after the universe grant was refused).
    2. If the group upload is refused, ask for a key owned by the group or by an account that manages its assets.
    3. Last, make the asset public (next item).
- **An asset another creator owns** (a key from a different account) must be public before the experience can load it. Images, decals and meshes start Open Use unless that account turned on Asset Privacy; sounds, videos and models start restricted, so grant them to everyone with `PATCH https://apis.roblox.com/asset-permissions-api/v1/assets/permissions` (beta; key scope `asset-permissions:write`; `subjectType` `All` with an empty `subjectId`, the ids in `requests`, `action` per the reference schema) or on the asset's Creator Hub permissions. Check `successAssetIds`, confirm each id loads in the experience, and report any that stay private.
