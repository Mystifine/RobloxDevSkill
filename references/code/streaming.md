# Streaming

Code for a place with `StreamingEnabled`, read from [coding.md](coding.md): which models arrive whole, binding to tagged models that stream in, and moving players between areas. The sign of a stream-out stall and how to measure it: [performance.md](performance.md).

- **Modes:** a model that must arrive whole gets `ModelStreamingMode = Atomic` (wait only on the model); one that must always exist, `Persistent` (wait for `Workspace.PersistentLoaded`); the default is `Nonatomic`. Prefetch with `Player:RequestStreamAroundAsync` before moving a player; `StreamOutBehavior = Opportunistic` is the recommended setting ([streaming](https://create.roblox.com/docs/workspace/streaming)). A place of several worlds keeps each player's own world whole with `PersistentPerPlayer`: `AddPersistentPlayer` for the world they are in, `RemovePersistentPlayer` for the rest (after travel the client held all 4,222 parts of its world and none of the last one).
- **A world streams part by part; each interactive model streams whole** *(default)*: keep each world model at `ModelStreamingMode` `Default` with `StreamOutBehavior` `Opportunistic`, and set `Atomic` on the models code binds to (stands, portals, stations, pads). A world kept as one `PersistentPerPlayer` model (12-15k parts, 15-18k instances, `StreamingTargetRadius` 1024, worlds 6000 studs apart) is one atomic unit: about 10 s after travel (`RemovePersistentPlayer` on the old world), one client frame took 4,901 ms removing 17,705 instances, the whole old world. A first fix, `StreamOutBehavior` `LowMemory`, removed the spike (no removal batch over two trips and four minutes; a second world kept loaded cost about 45 MB in Studio; arrival still cost one long frame, 234-255 ms for 15,421 instances, hidden in the travel), but kept every visited world loaded, and the owner wanted far content unloaded. Part by part, the same trip unloaded about 7,600 instances spread over many frames (no frame over 200 removed, the worst frame 51-64 ms), and a 1,600-stud jump inside a world peaked at 609 removed in an 8 ms frame. World spacing barely matters once parts stream singly: the atomic unit forced the one-frame removal. Client code that assumed one world present (a leaderboard screen moved to "the newest shrine") had to pick the current world's.
- **Set `Atomic` on every tagged interactive model in a part-streamed world:** a tagged Model's container reached the client at join without its parts (each far world showed about 1,000-1,400 container instances and no parts), so a `CollectionService` binder ran on an empty model, found no anchor or prompt, and never ran again: an egg stand with 9 of its 10 instances present had no label and a prompt that did nothing. `ModelStreamingMode` `Atomic` on every tagged model (432, of 10-113 instances each) made each arrive and leave whole; after a round trip every stand, portal, station and pad in the second world was bound and the egg window opened from its prompt. The tagging helper sets it.
- **Bind a tagged model once it stops growing; unbind when it leaves:** streaming can fire `CollectionService:GetInstanceAddedSignal` before the model's descendants arrive. Binders that looked up a child prompt with `FindFirstChild(name, true)` found a world's label anchor but not yet the part holding its `ProximityPrompt`, so `Triggered` was never connected: `ProximityPromptService` logged "triggered ShopPrompt" while nothing opened, and the UI state (no open view, no active menu) was clean, which ruled out a stuck window flag; the owner read it as "some state not toggled right". Waiting until a frame passes with no `DescendantAdded` (capped at 5 s), then binding, fixed eggs, shop and portal in the later worlds; unbinding on `GetInstanceRemovedSignal` keeps labels and connections from piling up when a world comes back.
- **Spawn in the right world before the first stream:** each world had a neutral `SpawnLocation`, so Roblox spawned the character at a random one before the server moved it home, and part streaming loaded 3,288 parts of an unrelated world 1,450-2,050 studs away. Setting `Player.RespawnLocation` to the saved world's spawn before `LoadCharacter` left only the home world's parts loaded on join (6,787).
