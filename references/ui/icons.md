# UI: icons and images

- **Robux prices use Roblox's native glyph,** U+E002 (the angular coin with a square hole): `utf8.char(0xE002)` or `"\u{E002}"`, never a drawn token, generic circle/hexagon or generated/uploaded imitation. Put glyph, space and amount in one native TextLabel when they share styling (`"\u{E002} 95"`), matched with `TextColor3` and a contextual `UIStroke`. It is a private-use character, not a universal Unicode currency sign: verify it renders (square hole, baseline) in the chosen font and client. [Roblox glyph reference](https://devforum.roblox.com/t/unicode-characters-for-roblox-plus-premium-verified-and-robux/2175425).
- **Match the selected image family:** its silhouettes, palette, shading, linework and border treatment ([visual-style.md](../art/visual-style.md)); add gloss, cartoon outlines or a sticker border only when the direction calls for them. Labels stay native text, except artwork intrinsic to an icon (a calendar's number).
- **An illustrated family stays image artwork for every subject,** small topbar checklist/clipboard, calendar and settings icons included: a simple subject is no license for stacked Frames, a Unicode/emoji glyph or a flat code-drawn icon beside painted/shaded art. Reuse a compatible image or make one through the fallback below. Native geometry suits layout, plates, borders, shine, simple plus/close marks, an explicitly geometric/vector family and the Robux glyph. Unobtainable art is a reported temporary placeholder, never a geometric substitute passed off as finished.
- **Reuse only consistent icons:** compare candidates side by side with the family, on the intended button faces at their rendered size and enlarged on a neutral background: outline color/weight and sticker borders, flat versus shaded/3D, lighting and gloss, palette, perspective, proportions, detail density, transparent edge quality. Project, plugin and Toolbox art alike, icons inside reused buttons included. The same subject, colors or a broad label such as "cartoon" is not enough; a flat emoji beside painted glossy icons fails unless the design mixes them explicitly. One stat or currency keeps the same artwork and treatment everywhere; functional groups use different families only when the reference or chosen design does.
- **Fallback when reuse fails:** search for a complete compatible set before mixing single finds (project images, then compatible plugin libraries and Toolbox art: [assets.md](../safety/assets.md)). Without one, create or edit coherent replacements in the selected style; if that is unavailable or out of the authorized scope, give the missing icons one consistent temporary placeholder treatment, mark them `Placeholder = true`, and report what is missing and how to replace it. Never fill gaps silently with incompatible art; source availability never changes the selected style.
- Generate icon **masters as 512x512, 1:1 (square), transparent-background PNG** *(default)*, kept in the project; downscale a generator's larger square output with premultiplied-alpha LANCZOS. If a generator cannot output transparency, remove the background and confirm the alpha channel before upload. Use a different size or aspect only for non-icon art (banners, hero art), with the user's agreement.
- **Size each upload for its largest use** *(default)*: pixels past the biggest box an image ever fills show nothing but cost texture memory (it grows with the square of the side: a 512 holds 4x a 256, 16x a 128) and load time. Take its biggest box on the largest supported screen, enlarged views included (a detail page, a reveal, a zoom), add headroom for dense phone screens, and upload the next common size (64, 128, 256, 512, 1024), downscaled from the master likewise. A fixed control never needs more than itself: menu and HUD buttons and inline icons 128-256, card portraits repeated in grids 256, 512 only for art shown large; Roblox scales anything over 1024 down. Note the size and why beside the upload (manifest or asset table); upload larger only when a larger use appears.
- **Character cards in grids and lists use flat 2D portraits** *(default)*, in the icon family's style; keep a ViewportFrame for one focused view (a detail page): a grid of cards each holding a live 3D portrait costs CPU.
- **Portrait references from the game's own rigs:** stand them in a grid on plain plates far from the map and pass `camera_position` and `look_at_position` to `screen_capture` with an image path (two shots each, full body and bust: 97 rigs, none failed, no image in context). Rigs exported without face decals capture with blank heads: give each its face in the prompt.
- **A set of similar icons:** one 1536x1024 sheet of six 512 cells per generation, sliced, then edges dilated to the target width: 12 emblems from three generations measured 21.5 to 22.2 px.
- **Emblems on cards** (a faction, a class) are bare symbols on transparency with a thick dark stroke (about 20-24 px at 512) inside the card's corner *(default)*, not floating badges with backgrounds.
- **No image generator free:** render the set in Blender. Flat shapes extruded with bevels, a Brick Texture node for tile relief, the Standard view transform, an orthographic shot of a tilted root and an ink edge dilated from the alpha matched a glossy simulator reference and read at 28 px. Relief comes from a procedural node: pixels written to a generated image and packed were lost.
- **Outlines match the set.** Before generating, measure the siblings' edge with [scripts/icon_outlines.py](../../scripts/icon_outlines.py) (a viewer shows transparency as white, hiding a white sticker border) and give every new or edited icon the same edge: a dark ink line, a white sticker border of the same width, or none. An edit never adds or drops a border; a brief states the measured style, never one remembered. Measure the width too: a generator drew a 20 px edge at 11-15 px at 512 in 18 attempts, retries did not help, and cropping to the shape and dilating its alpha did (7 px gave 17-18).
- **Character art** follows [characters.md](../safety/characters.md): put its garment line in the prompt and review at full size before upload.
- **Damage, health and defeat icons** are uploads and follow [no-gore.md](../safety/no-gore.md): a burst or star for damage, a heart for health, a cartoon skull or KO stars for defeats; never blood drops, splatter or wounds.
- **Uploads:** [uploading.md](../safety/uploading.md) (the project's cloud API key; they must load in the experience).
- For interactive UI, image ids live in the project's image-asset table (or one new constants module), never inline in controllers, so a replacement is one line. Static delivery uses the named asset values/attributes of [ui.md](ui.md), Static StarterGui work.
- For interactive UI, preload important images (`ContentProvider:PreloadAsync`) before the screen that needs them, and verify loads through the real ImageLabel/ImageButton (`IsLoaded`): a raw id-string preload can report Failure for a displayed asset, and a label in a closed window or off screen reports `IsLoaded` false and `GetAssetFetchStatus` Failure for images that load fine on screen. Static delivery needs a loading check in preview/Play, not a new preload script. For existence and size read `AssetService:CreateEditableImageAsync(Content.fromUri(id)).Size`; a freshly approved Decal's texture fails it for a few minutes.
- **Mirror an image** rather than uploading a flipped copy: `ImageRectOffset = (width, 0)` with `ImageRectSize = (-width, height)`, in the texture's pixels (its size: above; it read a group-owned texture's size on the client).
- **After generated art, audit every live image's size** against the size its use needs (above), not the files on disk: a handoff left one replacement never downscaled or uploaded, so a placeholder stayed live until the user caught it.
