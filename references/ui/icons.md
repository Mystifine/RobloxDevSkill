# UI: icons and images

- **Recognize Roblox's native Robux symbol:** the angular coin with a square hole is available as the Roblox-specific character U+E002: `utf8.char(0xE002)` or `"\u{E002}"`. Prefer that glyph for Robux prices instead of drawing a token, using a generic circle/hexagon, or generating/uploading an imitation. Put the glyph, a space, and the amount in one native TextLabel when they share styling (`"\u{E002} 95"`); use `TextColor3` and a contextual `UIStroke` to match the reference. This private-use character is not a universally supported Unicode currency sign: verify its actual rendering in the chosen font/client, including the square hole and baseline. See the [Roblox glyph reference](https://devforum.roblox.com/t/unicode-characters-for-roblox-plus-premium-verified-and-robux/2175425).
- **Match the selected image family:** preserve its silhouettes, palette, shading, linework and border treatment through [visual-style.md](../art/visual-style.md). Do not add gloss, cartoon outlines or a sticker border unless the direction calls for them. UI labels stay native text, except artwork intrinsic to an icon, such as a calendar's number.
- **Pictorial icons stay image artwork when their family is illustrated.** Use matching images for every subject in that family, including small topbar checklist/clipboard, calendar and settings icons. A simple subject is not permission to substitute stacked Frames, a Unicode/emoji glyph or a flat code-drawn icon beside painted/shaded artwork. Reuse a compatible image or create one through the same fallback workflow as larger icons. Native geometry remains appropriate for layout, plates, borders, shine, simple plus/close marks and an explicitly geometric/vector icon family; the native Robux glyph above is also an exception. If matching pictorial art cannot be obtained, mark and report a temporary placeholder instead of presenting the geometric substitute as finished.
- **Reuse is conditional on icon consistency:** compare candidate icons side by side with the selected family, on the intended button faces at their rendered size and enlarged on a neutral background. Check outline color/weight and sticker borders, flat versus shaded/3D treatment, lighting and gloss, palette, perspective, proportions, detail density, and transparent edge quality. Apply this to project, plugin and Toolbox art alike, including icons inside reused buttons. The same subject, colors, or broad label such as "cartoon" is insufficient; a flat emoji beside painted glossy icons fails this check unless that mix is explicit in the design. Repeated uses of one stat/currency must use the same artwork and treatment. Different functional groups may use different families only when supported by the reference or chosen design.
- **Fallback when reuse fails:** search for a complete compatible set before mixing individual finds. If matching art is unavailable, create or edit coherent replacements in the selected style when possible. If that is unavailable or outside the authorized scope, use a consistent temporary placeholder treatment for the missing icons, mark them `Placeholder = true`, and report what is missing and how to replace it. Do not silently fill gaps with stylistically incompatible art or present placeholders as a finished match. Search matching project images, then compatible plugin libraries and Toolbox art ([assets.md](../safety/assets.md)); source availability never changes the selected style.
- Generate icons as **512x512, 1:1 (square), transparent-background PNG** *(default)* (smaller memory on clients); downscale a generator's larger square output with premultiplied-alpha LANCZOS. If a generator cannot output transparency, remove the background and confirm the alpha channel before upload. Use a different size or aspect only for non-icon art (banners, hero art), with the user's agreement.
- **Outlines match the set.** Before generating, measure the siblings' edge with [scripts/icon_outlines.py](../../scripts/icon_outlines.py): a viewer shows transparency as white, which hides a white sticker border. Give every new or edited icon the same edge (a dark ink line, a white sticker border of the same width, or none). An edit never adds or drops a border, and a brief states the measured style, never one remembered.
- **Character art** follows [characters.md](../safety/characters.md): put its garment line in the prompt and review at full size before upload.
- **Damage, health and defeat icons** are uploads and follow [no-gore.md](../safety/no-gore.md): a burst or star for damage, a heart for health, a cartoon skull or KO stars for defeats; never blood drops, splatter or wounds.
- **Uploads** use the project's cloud API key and must load in the experience: [uploading.md](../safety/uploading.md).
- For interactive UI, all image ids live in the project's image-asset table (or one new constants module), never inline in controllers, so a replacement is a one-line change. Static instance delivery uses the named asset values/attributes of [ui.md](ui.md), Static StarterGui work.
- For interactive UI, preload important images (`ContentProvider:PreloadAsync`) before showing a screen that depends on them. Verify loads through the actual ImageLabel/ImageButton or its `IsLoaded` state: a raw id-string preload can report Failure even for a displayed asset. Static delivery needs a loading check in preview/Play, not a new preload script.
